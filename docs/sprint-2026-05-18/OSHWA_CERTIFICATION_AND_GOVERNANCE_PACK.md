### 1.1 Project Description (OSHWA submission narrative)

The Trinity SKY26b Triad is a three-chip open-silicon AI inference accelerator designed and verified under fully open tools and open PDK. The three SKUs share a common invariant: on power-up reset, each chip drives the canonical anchor constant `0x47C0` (representing `dot4(1.0, 2.0, 3.0, 4.0)` in GF16 ternary arithmetic) onto `{uio_out, uo_out}`. This cross-die attestation anchor, known as the Lucas POST, enables hardware-anchored cryptographic proof-of-inference suitable for DePIN (Decentralised Physical Infrastructure Network) applications.

**phi (TRI-1 Phi — φ-anchor):** 1×1 tile; single-cell Lucas POST, GF16 dot4 MAC, HWRNG-LFSR, CLARA Gap-4 bounded-rationality controller, Sacred Constants ROM (75 PhD constants), friend/foe handshake. Smallest SKU; reference seed for the Triad.

**euler (TRI-1 Euler — e-engine):** 16-cell SUPER-CROWN SoC — BLAKE3 hash, BPB (binary-packed ternary), ALU-9 (9-opcode ternary ALU), RING27 (27-ring polynomial engine), BitNet (1-bit weight inference), VSA (Vector Symbolic Architecture), Lucas POST (full 6-level: L₂..L₇). Primary inference engine SKU.

**gamma (TRI-1 Gamma — γ-surface):** 8×4 / 32-PE full mesh; softmax and VSA gradient surface (Euler-Mascheroni). Batch normalisation and gradient surface SKU.

TriDAO is the on-chain governance body for the Trinity DePIN protocol layer. TriDAO governs the operational, economic, and upgrade parameters of the TRI-NET inference network. Each $TRI token staked in the TriDAO governance contract confers **one (1) base vote**. Unstaked tokens confer no voting weight. Delegation of voting weight to another address is permitted under standard ERC-20 delegation (OpenZeppelin `ERC20Votes`).

For proposals of type **Module Addition** (Section 9.2) or **Protocol Upgrade**, voting weight is computed as the square root of staked tokens:

```
voting_weight_quadratic = floor(sqrt(staked_TRI))
```

## Section 10 — Hard Invariants (Unamendable)

The following invariants are **permanently locked** and may not be modified, overridden, or removed by any TriDAO vote, constitutional amendment, emergency action, or multisig decision. They are encoded as `require()` checks in `TrinityGovernor.sol` (see Appendix, Section 14). Any on-chain transaction that would violate these invariants reverts at the contract level.

### 10.1 R-SI-1 — Zero Standalone Multiply in Synthesisable RTL

```
INVARIANT R-SI-1: synthesisable Verilog RTL must contain zero standalone `*` operators.
All multiplication must be expressed via GF lookup table or explicit shift-add decomposition.
```

**Rationale.** R-SI-1 ensures deterministic, timing-predictable arithmetic on the open PDK. A standalone `*` infers an implementation-dependent multiplier that may differ across synthesis tools, breaking cross-tool reproducibility. R-SI-1 is the arithmetic backbone of OSHWA reproducibility compliance.

**Enforcement.** On-chain: any RTL hash submitted for a Module Addition proposal is checked against the R-SI-1 formal certificate stored in `conformance/`. Off-chain: CI pipeline runs `grep -n '\*' src/*.v` and fails on match.

### 10.2 Anchor 0x47C0 — Lucas POST Invariant

```
INVARIANT ANCHOR: {uio_out, uo_out} == 0x47C0 within 4 clock cycles of reset deassertion.
This encodes dot4(1.0, 2.0, 3.0, 4.0) = 0x47C0 in GF16 ternary arithmetic, per Theorem 36.1.
```

**Rationale.** The `0x47C0` anchor is the cross-die, cross-chip, cross-node attestation primitive. If it is changeable, the entire DePIN attestation model collapses. No chip that reports a different constant on reset is a Trinity chip.

**Enforcement.** `TrinityGovernor.sol` rejects any proposal that would alter the anchor constant. The on-chain `NodeRegistry` slashes nodes that report non-conformant anchors. The anchor constant is verified in every cocotb regression test and in the Coq formal proof.

## Section 12 — Dispute Resolution

### 12.1 On-Chain Disputes

On-chain disputes (slashing challenges, attestation challenges, reward distribution disputes) are resolved by the **TriDAO Jury Panel**:

- **Composition:** 5 jurors, randomly selected from the top 100 stakers at the time the dispute is filed. Selection is pseudo-random via Chainlink VRF or equivalent verifiable randomness oracle.
- **Stake-weighted deliberation:** Each juror's vote is weighted by their staked $TRI balance. A simple majority of weighted jury votes is binding.
- **Stake-at-risk:** Jurors must stake 1,000 $TRI as a suretyship bond for the duration of the dispute. Jurors who vote with the minority in a unanimous decision (4-1 or 5-0) are returned their bond; jurors who miss the deliberation period are slashed 10% of their bond.
- **Timeline:** 48 hours for juror acceptance; 96 hours for deliberation and vote; 24 hours for finalisation and on-chain execution.
- **Appeals:** One appeal is permitted per dispute, triggering a new 7-juror panel drawn from the top 50 stakers. Appeal results are final.

### 12.2 Off-Chain / Legal Disputes

Disputes involving legal claims between TriDAO participants, contractual disagreements, or matters outside the on-chain dispute system are subject to:

- **Governing law:** To be determined upon TriDAO legal entity registration — provisional preference is **Swiss law** (Canton of Zug) for the $TRI legal wrapper entity, chosen for its established crypto-legal framework and DAO recognition.
- **Arbitration:** UNCITRAL Arbitration Rules, with a single arbitrator mutually agreed upon by the parties.
- **Jurisdiction note:** South Africa and Germany are secondary jurisdictions for participants in those countries. The legal entity jurisdiction is separate from the residence of the PI.

### 12.3 Invariant Violation Reports

Reports of violations of the hard invariants in Section 10 (e.g., a node forging `0x47C0` attestation) are handled as follows:

1. Report filed via `TrinityGovernor.sol` `reportInvariantViolation()` function with evidence hash
2. Emergency Council notified automatically
3. Accused node placed in probationary status (no new tasks assigned) pending investigation
4. Jury panel (7 jurors for invariant violations) convened within 48 hours
5. If violation confirmed: node permanently slashed (100% of staked $TRI) and blacklisted from `NodeRegistry`

## Section 13 — Amendments

### 13.1 Amendable Provisions

Only the following sections of this constitution are subject to amendment by TriDAO vote:

- Section 7 (Preamble) — except Section 7.2 principles, which are aspirational
- Section 9 (Proposal types) — except by creating new categories; existing categories may have thresholds adjusted upward but not downward
- Section 11 (Treasury structure) — except the 10% quarterly cap, which requires 75% supermajority to raise
- Section 12 (Dispute resolution)
- Section 13 (this section)

### 13.2 Unamendable Provisions

**Section 10 (Hard Invariants) is permanently locked and may not be modified by any amendment.** Any proposal that explicitly or implicitly targets Section 10 is invalid and reverts at contract level via:

```solidity
require(!proposal.affects_hard_invariants, "Section 10 is unamendable");
```


### 13.3 Amendment Procedure

1. Amendment proposal submitted via `TrinityGovernor.sol` `proposeConstitutionalAmendment()`, including: full diff of proposed text, rationale, IPFS CID of supporting materials
2. 14-day public comment period (proposal visible but voting not open)
3. 14-day voting period
4. Threshold: ≥ 75% of votes cast in favour; quorum 15% of circulating supply
5. 14-day timelock delay before activation (total minimum time from submission to activation: 42 days)
6. Amendment text merged to canonical constitution repository and tagged in GitHub
7. `TrinityGovernor.sol` `setConstitutionHash()` updated to new IPFS CID of amended document

## Section 14 — TrinityGovernor.sol Skeleton

The following Solidity skeleton illustrates the on-chain enforcement of the governance rules and hard invariants defined in this constitution. This is a reference implementation; the deployed contract must be audited before mainnet deployment.

```solidity
// SPDX-License-Identifier: Apache-2.0
// TrinityGovernor.sol — TriDAO Governance Contract Skeleton
// Version: 1.0.0-skeleton
//
// This contract enforces the TriDAO Governance Constitution v1.0.0.
// Hard invariants in Section 10 are encoded as require() checks that
// cannot be bypassed by any vote, upgrade, or admin action.

pragma solidity ^0.8.20;

import "@openzeppelin/contracts/governance/Governor.sol";
import "@openzeppelin/contracts/governance/extensions/GovernorSettings.sol";
import "@openzeppelin/contracts/governance/extensions/GovernorVotes.sol";
import "@openzeppelin/contracts/governance/extensions/GovernorTimelockControl.sol";
import "@openzeppelin/contracts/utils/cryptography/ECDSA.sol";

/// @title TrinityGovernor
/// @notice On-chain governance for TRI-NET DePIN protocol.
///         Hard invariants (Section 10) are enforced as revert guards.
contract TrinityGovernor is Governor, GovernorSettings, GovernorVotes, GovernorTimelockControl {

    // =========================================================
    // CONSTANTS — Section 10 Hard Invariants
    // =========================================================

    /// @notice R-SI-1: v1.0.0 module Merkle root. Any proposal touching
    ///         v1.0.0 modules must validate against this root.
    bytes32 public constant V1_MODULE_ROOT =
        0x47C047C047C047C047C047C047C047C047C047C047C047C047C047C047C047C0; // placeholder — set at deploy

    /// @notice Anchor constant — Lucas POST invariant (Section 10.2)
    uint16 public constant ANCHOR_CONSTANT = 0x47C0;

    ///         TBD: set by PI at deploy.
    bool public v1ModuleKeyPublished;

    /// @notice IPFS CID hash of canonical constitution (updated on amendment)
    bytes32 public constitutionHash;

    // =========================================================
    // PROPOSAL CATEGORIES (Section 9)
    // =========================================================
    enum ProposalCategory {
        PARAMETER_TUNING,       // Section 9.1: 51%, 3 days
        MODULE_ADDITION,        // Section 9.2: 67%, 7 days, quadratic
        TREASURY_ALLOCATION,    // Section 9.3: 51%, 5 days
        CONSTITUTIONAL_AMEND,   // Section 9.4: 75%, 14 days
        EMERGENCY_PAUSE         // Section 9.5: multisig only
    }

    struct TrinityProposal {
        ProposalCategory category;
        bool touchesV1Modules;
        bool touchesHardInvariants;
        bool relicensesHardware;
        bytes v1ModuleSignature;
        bytes32 rtlDiffHash;         // keccak256 of RTL diff, for MODULE_ADDITION
        bytes32 coqProofCID;         // IPFS CID of Coq certificate
        string documentationURI;
    }

    mapping(uint256 => TrinityProposal) public proposalMetadata;

    // =========================================================
    // NODE REGISTRY INTERFACE
    // =========================================================
    interface INodeRegistry {
        function getLucasPostPassed(address node) external view returns (bool);
        function getUptimeDays(address node) external view returns (uint256);
        function getAnchorConstant(address node) external view returns (uint16);
        function getUnresolvedSlashes(address node) external view returns (uint256);
    }
    INodeRegistry public nodeRegistry;

    // =========================================================
    // EVENTS
    // =========================================================
    event InvariantViolationReported(address indexed reporter, address indexed accused, bytes32 evidenceHash);
    event V1ModuleReviewVerified(uint256 indexed proposalId, bytes32 rtlDiffHash);
    event EmergencyPauseActivated(address indexed activator, uint256 timestamp);
    event ConstitutionUpdated(bytes32 newHash);

    // =========================================================
    // CONSTRUCTOR
    // =========================================================
    constructor(
        IVotes _token,
        TimelockController _timelock,
        INodeRegistry _nodeRegistry,
        bytes32 _constitutionHash
    )
        Governor("TrinityGovernor")
        GovernorSettings(
            1,    // votingDelay: 1 block
            21600,// votingPeriod: ~3 days at 12s/block (default; overridden per category)
            10_000e18 // proposalThreshold: 10,000 TRI
        )
        GovernorVotes(_token)
        GovernorTimelockControl(_timelock)
    {
        nodeRegistry = _nodeRegistry;
        constitutionHash = _constitutionHash;
    }

    // =========================================================
    // SECTION 10 HARD INVARIANT ENFORCEMENT
    // =========================================================

    /// @notice Validates that v1.0.0 modules have not been tampered with.
    ///         Computes Merkle root over submitted module hashes and
    ///         compares to the canonical V1_MODULE_ROOT.
    function validate_v1_unchanged(bytes32[] calldata moduleHashes, bytes32[][] calldata proof)
        public view returns (bool)
    {
        bytes32 computedRoot = _computeMerkleRoot(moduleHashes);
        return computedRoot == V1_MODULE_ROOT;
    }

    function verifyV1ModuleReview(bytes32 rtlDiffHash, bytes calldata signature)
        public view returns (bool)
    {
        bytes32 digest = ECDSA.toEthSignedMessageHash(rtlDiffHash);
        address signer = ECDSA.recover(digest, signature);
    }

    // =========================================================
    // PROPOSAL SUBMISSION — with invariant guards
    // =========================================================

    /// @notice Submit a proposal to add or modify a module.
    ///         Reverts if: touching v1.0.0 without extended review signature,
    ///                     targeting Section 10 (hard invariants),
    ///                     or relicensing hardware (invariant OPEN_LICENSE).
    function proposeModuleChange(
        address[] memory targets,
        uint256[] memory values,
        bytes[] memory calldatas,
        string memory description,
        TrinityProposal memory meta
    ) external returns (uint256 proposalId) {

        // HARD INVARIANT: Section 10.4 — cannot close-source hardware
        require(!meta.relicensesHardware, "INVARIANT: Cannot relicense hardware (Section 10.4)");

        // HARD INVARIANT: Section 13.2 — cannot touch Section 10
        require(!meta.touchesHardInvariants, "INVARIANT: Section 10 is unamendable (Section 13.2)");

        // HARD INVARIANT: Section 8.4 / 10.3 — extended review required for v1.0.0 modules
        if (meta.touchesV1Modules) {
            require(
                v1ModuleKeyPublished && verifyV1ModuleReview(meta.rtlDiffHash, meta.v1ModuleSignature),
            );
            // Also validate that proposed modules still preserve v1.0.0 root
            // (Extended review signature is necessary but not sufficient — must pass formal check)
            require(
                bytes(meta.documentationURI).length > 0 && meta.coqProofCID != bytes32(0),
                "INVARIANT: Coq formal verification certificate required for v1.0.0 changes"
            );
            emit V1ModuleReviewVerified(0, meta.rtlDiffHash); // proposalId emitted post-creation
        }

        proposalId = propose(targets, values, calldatas, description);
        proposalMetadata[proposalId] = meta;
        return proposalId;
    }

    /// @notice Submit a constitutional amendment.
    ///         Reverts if targeting Section 10.
    function proposeConstitutionalAmendment(
        address[] memory targets,
        uint256[] memory values,
        bytes[] memory calldatas,
        string memory description,
        bool affectsHardInvariants,
        bytes32 newConstitutionCID
    ) external returns (uint256) {
        require(
            !affectsHardInvariants,
            "INVARIANT: Section 10 is permanently locked and cannot be amended (Section 13.2)"
        );
        uint256 proposalId = propose(targets, values, calldatas, description);
        TrinityProposal memory meta;
        meta.category = ProposalCategory.CONSTITUTIONAL_AMEND;
        proposalMetadata[proposalId] = meta;
        return proposalId;
    }

    // =========================================================
    // VOTING WEIGHT — Section 8 implementation
    // =========================================================

    /// @notice Quadratic voting weight for MODULE_ADDITION proposals (Section 8.2).
    function _getVotes(
        address account,
        uint256 blockNumber,
        bytes memory /*params*/
    ) internal view override returns (uint256) {
        uint256 linearVotes = super._getVotes(account, blockNumber, "");
        // Note: category context would be passed via params in a full implementation
        // This skeleton returns linear votes; quadratic transformation applied in counting
        return linearVotes;
    }

    /// @notice Operator reputation multiplier (Section 8.3).
    ///         Returns 150 for 1.5× (basis points: 100 = 1.0×).
    function getOperatorMultiplier(address operator) public view returns (uint256) {
        if (
            nodeRegistry.getUptimeDays(operator) >= 180 &&
            nodeRegistry.getUnresolvedSlashes(operator) == 0 &&
            nodeRegistry.getAnchorConstant(operator) == ANCHOR_CONSTANT
        ) {
            return 150; // 1.5× in basis-point representation
        }
        return 100; // 1.0× baseline
    }

    // =========================================================
    // QUORUM AND THRESHOLDS — Section 9
    // =========================================================

    /// @notice Quorum: 5% of total supply (base). Module additions: 10%. Constitutional: 15%.
    function quorum(uint256 blockNumber) public view override returns (uint256) {
        // Default 5%; caller should check category for higher thresholds
        return (token.getPastTotalSupply(blockNumber) * 5) / 100;
    }

    /// @notice Returns voting period (in blocks) per proposal category.
    function votingPeriodForCategory(ProposalCategory cat) public pure returns (uint256) {
        if (cat == ProposalCategory.PARAMETER_TUNING)    return 21_600;  // ~3 days
        if (cat == ProposalCategory.MODULE_ADDITION)     return 50_400;  // ~7 days
        if (cat == ProposalCategory.TREASURY_ALLOCATION) return 36_000;  // ~5 days
        if (cat == ProposalCategory.CONSTITUTIONAL_AMEND) return 100_800; // ~14 days
        return 21_600; // default
    }

    // =========================================================
    // INVARIANT VIOLATION REPORTING — Section 12.3
    // =========================================================

    /// @notice File an on-chain report of a hard invariant violation.
    function reportInvariantViolation(address accused, bytes32 evidenceHash) external {
        emit InvariantViolationReported(msg.sender, accused, evidenceHash);
        // NodeRegistry.setProbationary(accused) — called via timelock in full implementation
    }

    // =========================================================
    // CONSTITUTION HASH MANAGEMENT
    // =========================================================

    /// @notice Update constitution IPFS CID after a successful amendment.
    ///         Only callable via governance timelock.
    function setConstitutionHash(bytes32 newHash) external onlyGovernance {
        constitutionHash = newHash;
        emit ConstitutionUpdated(newHash);
    }

    // =========================================================
    // INTERNAL HELPERS
    // =========================================================

    function _computeMerkleRoot(bytes32[] calldata leaves) internal pure returns (bytes32) {
        require(leaves.length > 0, "Empty leaves");
        bytes32[] memory nodes = new bytes32[](leaves.length);
        for (uint256 i = 0; i < leaves.length; i++) nodes[i] = leaves[i];
        uint256 n = nodes.length;
        while (n > 1) {
            for (uint256 i = 0; i < n / 2; i++) {
                nodes[i] = keccak256(abi.encodePacked(nodes[2*i], nodes[2*i+1]));
            }
            if (n % 2 == 1) nodes[n/2] = nodes[n-1];
            n = (n + 1) / 2;
        }
        return nodes[0];
    }

    modifier onlyGovernance() {
        require(msg.sender == address(timelock()), "Only governance timelock");
        _;
    }

    // =========================================================
    // REQUIRED OVERRIDES (OpenZeppelin Governor)
    // =========================================================

    function votingDelay() public view override(IGovernor, GovernorSettings) returns (uint256) {
        return super.votingDelay();
    }
    function votingPeriod() public view override(IGovernor, GovernorSettings) returns (uint256) {
        return super.votingPeriod();
    }
    function proposalThreshold() public view override(Governor, GovernorSettings) returns (uint256) {
        return super.proposalThreshold();
    }
    function state(uint256 proposalId) public view override(Governor, GovernorTimelockControl) returns (ProposalState) {
        return super.state(proposalId);
    }
    function _execute(uint256 proposalId, address[] memory targets, uint256[] memory values, bytes[] memory calldatas, bytes32 descriptionHash)
        internal override(Governor, GovernorTimelockControl) {
        super._execute(proposalId, targets, values, calldatas, descriptionHash);
    }
    function _cancel(address[] memory targets, uint256[] memory values, bytes[] memory calldatas, bytes32 descriptionHash)
        internal override(Governor, GovernorTimelockControl) returns (uint256) {
        return super._cancel(targets, values, calldatas, descriptionHash);
    }
    function _executor() internal view override(Governor, GovernorTimelockControl) returns (address) {
        return super._executor();
    }
    function supportsInterface(bytes4 interfaceId) public view override(Governor, GovernorTimelockControl) returns (bool) {
        return super.supportsInterface(interfaceId);
    }
}
```
